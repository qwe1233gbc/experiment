## 3. RAG 接入方案（分三阶段，按依赖排序）

### 阶段一：纯代码增强（零外部依赖，可立即做）

改造点均在 `api/rag/retriever.py`，保持 `retrieve(query, kb_text, top_k, synonyms)` 签名兼容，`engine.py::retrieve_refs()` 调用方不动：

1. **精确代码加权**：对报告/查询中出现的标准号（如DB44/2367-2022）、行业代码（如C2927）在BM25得分上加权250、文件名完全匹配加权500——科研验证这是防止"字面相似稀释精确匹配"的关键修正（来源：01号文档§4）；
2. **来源多样化约束**：候选池单源上限3个子块——修复"同一规范相邻子块挤占候选池"的召回退化（21题阶段实测问题）；
3. **BM25参数与分词对齐**：k1=1.5、b=0.75、中文unigram+bigram（科研冻结参数），并把召回窗口从当前top_k扩大到Top-100再截断。

### 阶段二：父子分块 + Dense双路 + RRF（核心升级）

1. **知识库重建为parent-child结构**：用科研冻结参数（o200k_base tokenizer、父块4000、子块500、重叠100）对6个现有md库及后续导入库重新分块；子块为检索单元、父块为返回单元——工程侧现有`split_segments()`可保留为兼容回退；
2. **Dense路**：text-embedding-v4（1024维，cosine）仅对子块嵌入，FAISS IndexFlatIP索引（科研即用IndexFlatIP，3459子块规模下无需GPU/专用向量库，单机内存即可承载）；
3. **RRF融合**（k=60）+ 候选池Top-30 → 与阶段一加权协同。

**前置依赖**：DashScope embedding key（工程历史取消原因即无key）——这是本阶段唯一的硬依赖，需在部署侧解决。

### 阶段三：rerank + Top-5 + parent扩展

1. gte-rerank-v2对候选池Top-30精排（精确来源加成+1.0）；
2. 来源去重后扩展回父块（≤4000 token完整上下文）输出Top-5——替代当前"片段直接进提示词"的模式；
3. **前置依赖**：rerank API访问（与embedding同一供应商，可一并解决）。

**预期收益的科研依据**（必须如实表述）：40题v3.1快照在81源库上Top-5召回质量37A/2B/1C、新增知识19/19进Top-3且全部Top-1、21/21预期源覆盖（来源：01号文档§5）；该数字证明的是**检索层质量**，工程端到端收益需按§5方法学另行验收。

## 4. Skill 接入方案（升级现有 rules/，而非另起炉灶）

现有11条规则 = `config.txt`（声明式配置）+ `extract_prompt.txt` + `review_prompt.txt`，本质是提示词规则库。升级路径：

| 升级项 | 现状 | 目标（对齐科研Skill 15节结构） | 改造位置 |
|---|---|---|---|
| 结构化审核程序 | 判断逻辑写在自然语言提示词内 | 每条规则的review_prompt按"触发条件→证据字段→分步程序→降级规则→输出契约"重写 | `rules/rule_xx/review_prompt.txt` |
| 证据字段契约 | 提示词内隐式要求 | 显式字段表（如排放标准规则11字段：污染源/工艺/污染因子/介质/排放形式/去向/治理设施/报告标准/限值/排口参数/报告日期），每字段绑定quote+位置 | 同上 |
| 输出契约 | 自由文本+JSON混合 | 统一JSON：conclusion五级（匹配/不匹配/部分匹配/无法判断/不适用）+ basis_status三态 + missing_evidence + manual_review_needed | 同上 + `engine.py`解析 |
| 降级纪律 | 无系统化降级 | "RAG不足→basis_status=insufficient→无法判断"，**禁止把'未检索到依据'判成'报告错误'** | 同上 |
| 版本路由 | 无 | 广东VOCs核算方法2021试行/2023修订按报告编制时点路由（manual_policy_files模式，不进RAG语料） | 规则配置层 |
| 路由调度 | 11条规则全部并行执行 | 按科研路由器"最小充分集合+领域依赖顺序"（行业分类→建设内容→排放标准；收集形式→设计风量→收集效率→活性炭→VOCs总量）组织执行链 | `pipeline.py::run_yushen()` |

**优先升级对象建议**（按科研实验证据排序）：
1. 排放标准类规则（对应review-eia-pollutant-discharge-standards）——知识核验型任务，正向交互最集中（+0.8~+1.0）；
2. 产污系数/源强核算类规则——RAG受益任务（+0.500/+1.000）；
3. 建设内容完整性规则——Skill程序价值任务（案例B）；
4. **行业分类/投资类规则暂缓深度改造**——V01类是唯一负交互（-0.400），现有简单提示词已够用。

## 5. 验收方法学迁移（把2×2做成工程回归框架）

科研的实验基建可直接转为工程的上线验收协议：

1. **Gold基准集**：48题人工确认Gold（40题Gold最终人工核验20260820 + 21题冻结评价集）作为工程回归测试集；
2. **冻结快照对拍**：RAG接入前后对同一批查询跑检索对拍（对应科研的`retrieval_manifest.json`+SHA256机制），保证升级可回滚、可归因；
3. **A/B消融上线**：新模块（混合RAG、Skill化规则）以开关形式接入，线上按§4的任务分层灰度——知识核验型规则先开，V01类规则不开；
4. **LLM盲评**：192条回答匿名盲评协议（R1–R4）作为CI质量门禁，QC 15项检查脚本化。

## 6. 依赖、风险与边界

| 项 | 说明 |
|---|---|
| 硬依赖 | DashScope embedding + rerank key（阶段二/三）；无key时阶段一仍可独立交付（精确加权+单源上限+参数对齐） |

| 算力/延迟 | IndexFlatIP在数千子块规模毫秒级；rerank增加一次API调用（Top-30→Top-5），预审11规则并行时需评估并发 |
| 表述边界 | 接入完成前，工程现状仍应表述为"BM25关键词检索"而非"混合RAG"；规则提示词不得称为"已实现Skill"——两者结构差异见§4 |
| 不改动项 | Java回调契约、共享目录集成、无数据库架构、填报链路——全部保持不动 |

## 7. 接入优先级总结（一句话）

> 先做零依赖的检索质量修正（精确代码加权、单源上限、参数对齐），再解决key依赖落地混合检索（父子分块→Dense+RRF→rerank），同步把11条规则提示词升级为带输入输出契约与降级纪律的Skill结构，最后用48题Gold集+冻结对拍做上线验收——每一步都在现有FastAPI链路内增量完成。
