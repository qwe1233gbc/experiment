## 主线

```
环评审核需要精确的法规依据（LLM记忆不可靠）
        ↓
法规知识按"四层架构"组织（全文→卡片→分块→Skill路由）
        ↓
Query 从报告事实构造（question + key_facts + evidence_windows，v3.1）
        ↓
BM25稀疏召回 + Dense稠密召回（双路）
        ↓
RRF融合 → 精确代码加权 → 候选池（单源≤3、Top-30）
        ↓
gte-rerank-v2 神经重排 → 来源去重 → parent扩展
        ↓
Top-5 Evidence（可追溯 source_id + parent原文）
        ↓
进入 B/D 组 LLM 审核提示词
```

## 1. 为什么需要 RAG（问题起点）

环评审核是**证据密集、规则约束强**的专业判断：判断设计风量是否合理需要 HJ 2026-2013 的漏风系数与120%规则；判断产污系数是否适用需要系数手册的工艺边界条目；判断危废代码需要《国家危险废物名录》。这些依据**版本多、层级多（国/省/市/区）、地方性极强**（佛山市顺德区镇级污水处理标准、广东VOCs核算方法2021试行版与2023修订版），超出通用大模型参数化记忆的可靠范围。

科研实验中的直接证据：PL007_DesignAirflow_Q01（设计风量题），裸模型A组把"设计风量仅比理论风量高8.5%"判为"合理"——因为它不知道知识库规定的"漏风系数一般取10%~20%"这一外部规则；B/D组拿到RAG证据后正确判定"设计余量不足"。judge评语："虽正确复算理论风量并指出余量8.5%，但未识别该余量低于规范最低要求，导致关键审核结论错误。"
（来源：`09_机制分析准备_20260822/06_典型题ABCD对照.md` §D）

## 2. 环评知识怎么组织（四层架构）

四层架构正式库（`04_知识库构建/四层架构_正式库/README.md`，2026-08-10构建/08-11第三层重构）：

| 层级 | 产物 | 最终规模 |
|---|---|---|
| 第1层 | 法规、标准、指南及结构化辅助知识源（官方来源核验+SHA256登记） | 52项（基础）→ 81项（最终） |
| 第2层 | 标准卡片（规则型/全文型，结构化"何时用哪条标准"） | 38张（28规则型+10全文型） |
| 第3层 | 全文级 RAG 检索层（父子分块+向量+BM25混合索引） | 81源/409父块/3459子块 |
| 第4层 | Skill 检索路由（见02号文档） | 15个专业Skill+1个总路由器 |

**层级化父子分块（parent-child）**（来源：`version_manifest_20260820.json` 与 `README_61题扩展版.md`，全程冻结未变）：

| 参数 | 值 |
|---|---|
| tokenizer | o200k_base（与 qwen3.8-max 一致） |
| parent_target_tokens | 4000（父块=完整法规上下文） |
| child_window_tokens | 500（子块=检索单元） |
| child_overlap_tokens | 100（20%重叠） |
| embedding | text-embedding-v4，1024维，cosine，**仅子块嵌入** |
| 索引 | FAISS IndexFlatIP（L2归一化后内积=余弦）+ BM25 |

设计意图：**子块精检索、父块还原完整法规上下文**——避免"同一份长规范相邻子块大量占据候选池"的召回退化（该问题在21题首版候选快照诊断中发现并修正，来源：`第三阶段_候选快照验收报告_20260812.md` §4）。

**知识源构成与内容纪律**（81源新增8源即典型样本，来源：`version_manifest_20260820.json`）：
- 产污系数手册行业摘录（#23机械33-37/431-434、#24电子电气38-40、#25涂料2641、#26废弃资源4220）；
- 审核指南（#27源强闭合核算、#28活性炭参数、#29 VOCs总量一致性、#30废气收集与排风量）；
- 每源绑定 `source_id`（SRC001–SRC081）、SHA256、来源分类、对应Skill、覆盖任务；
- **语义边界固化**：#28"15%吸附比例仅作为广东2023方法建议核算值""20%不得作通用规范值"；#30"HJ2026-2013设计风量宜按最大废气排放量120%是规范依据，周长法Q=K×P×H×V×3600与12/60次换气仅为工程参考"——全量chunk扫描确认"15%–20%合并表述""GB/T16758规定"等被禁表述0命中（来源：`新增知识入库执行报告_20260820.md` §5）。

**版本路由机制（地方规则时效性）**：广东VOCs核算方法2021试行版与2023修订版收集效率不同（单层密闭负压95→90%、单层密闭正压85→80%、双层密闭99→98%、设备排口直连95%不变）。处理方式：版本路由文件存放于 Skill 路由层 manual_policy_files（**不进入RAG语料、不占业务源编号**），注册到3个相关Skill；规则为"报告编制/评价时点→判断当时有效版本→检索对应参数，禁止版本混用、禁止用2023规则倒推历史报告"。（来源：`新增知识入库执行报告_20260820.md` §4）

**数据隔离**：待审核环评报告JSON（`01_原始文件输入`）是模型的审核对象，**不进入**任何父块/子块/向量/BM25索引（来源：`四层架构_正式库/README.md`、`README_目录说明.md`）。

## 3. Query 怎么构造（v3.1，问题—修复—验证的真实演化）

**构造原则**（21题阶段即冻结，来源：`第三阶段_候选快照验收报告_20260812.md` §3）：
查询仅由 ① 问题文本、② 报告证据锚点附近短窗口、③ 报告中出现的标准号/行业代码/污水处理厂/受纳水体/污染因子 构成；**明确排除** reference_answer、basis_status、manual_review_required 及人工结论。

**版本演化**（40题阶段，来源：`40题_v3_1落地验收报告_20260820.md`）：

```
v1/v2（question + key_facts + evidence_windows）
  → v3（evidence_windows 重抽取）
  → v3.1（KF 噪声清理：4题跨任务残留噪声删除；5题A类恢复v2原版KF（A_preserved）；
          PL008两题粘连数字仅记录不判失败）
  → 40/40 验收通过，变更字段仅限 key_facts/query/query_sha256/repair_basis
```

**真实失败案例（最适合展览的"问题—修复—验证"故事）**：

PL009_Construction_Q01（建设内容完整性题）：
- **现象**：旧版冻结快照中该题候选池只命中4个来源（4-hit），且候选池12个child**全部来自4个"三线一单"源**——报告第一章的"三线一单"管控内容主导了证据窗口，把检索带偏到无关法规；
- **修复**：v3.1重写该题query的关键事实后，**未新增任何fallback逻辑**，候选池自然恢复5个不同来源（SRC015、SRC055、SRC056、SRC060、SRC061）；
- **结论（原文）**："旧4-hit由query前处理偏差导致（旧query证据窗口被'三线一单'内容主导，候选池12个child全部来自4个三线一单源）。"
（来源：`40题冻结RAG快照_v3_1_20260820/冻结RAG验收报告.md` §4.4）

**修复的量化收益**（同上报告 §3–4）：

| 指标 | 旧版（v1 query） | v3.1 | 变化 |
|---|---|---|---|
| Top-5召回质量评级 | 24A / 11B / 5C | **37A / 2B / 1C** | B+C从16题降至3题 |
| 0命中设计源的题数 | 15 | 1 | 恢复14/15 |
| 原A题退化 | — | 无 | 修复不引入退化 |

**Query防泄漏**：40题快照自动验收13项全PASS，其中Gold leakage=0（query≥20字、context≥40字滑窗检查）、Skill leakage=0；query仅由 question + key_facts + evidence_windows + missing_slots 构成。（来源：`冻结RAG验收报告.md` §2、§6）

## 4. 如何召回、融合、重排（正式检索链路与参数）

全部参数冻结一致，40题快照与21题快照逐参数对齐（来源：`40题冻结RAG快照_v3_1_20260820/retrieval_manifest.json`、`冻结RAG验收报告.md` §1；21题链路描述见`第三阶段_候选快照验收报告_20260812.md`）：

| 节点 | 参数/配置 | 说明 |
|---|---|---|
| BM25 稀疏召回 | k1=1.5，b=0.75，中文unigram+bigram，sparse_top_k=**100** | BM25召回从Top-N扩大到Top-100是21题阶段修正项（原中文逐字/二元词稀释标准号精确匹配） |
| Dense 稠密召回 | text-embedding-v4（1024维，cosine），FAISS IndexFlatIP，dense_top_k=**40** | 仅子块嵌入 |
| RRF 融合 | rrf_k=**60** | 双路排名融合 |
| 精确代码加权 | BM25精确代码加权 **250**、文件名完全匹配 **500**；rerank精确来源加成 **+1.0** | 报告明确出现的标准号/行业代码确定性提权，防止字面相似稀释精确匹配 |
| 候选池 | candidate_top_k=**30**，单源上限 **3个子块** | 来源多样化约束（同一规范相邻子块挤占候选池的修正） |
| 神经重排 | **gte-rerank-v2** | 语义精排 |
| 来源去重 + parent扩展 | 是 | Top-5按知识源去重后扩展回父块（≤4000 tokens完整上下文） |
| 最终输出 | final_top_k=**5**，每题恰好5个互不重复来源 | B/D组共用同一冻结快照，禁止实时重检索 |

链路还原（每节点参数均有上述来源支撑）：

```
审核任务（question_id）
↓
Query构造（v3.1：question + key_facts + evidence_windows + missing_slots；排除Gold/Skill）
↓
BM25 Sparse Retrieval（k1=1.5/b=0.75，Top-100，精确代码加权250/文件名500）
        +
Dense Embedding Retrieval（text-embedding-v4，1024维，FAISS，Top-40）
↓
RRF融合（k=60）→ 候选池Top-30（单源≤3）
↓
Rerank（gte-rerank-v2，精确来源加成+1.0）→ 来源去重 → parent扩展
↓
Top-5 Evidence（source_id可追溯 + 父块完整原文）
↓
LLM审核（B/D组，qwen3.8-max，temperature=0）
```

## 6. 面向展览的RAG一句话表达

> RAG把81个官方法规知识源组织成"子块精确检索、父块还原上下文"的层级证据库，通过 BM25+向量双路召回、RRF融合、精确代码加权与神经重排，为每道审核题提供**可追溯到 source_id 的 Top-5 法规证据**——并以"21/21预期源覆盖、19/19新增知识Top-1、40题召回37A/2B/1C"三层验收数字证明其可靠性；query构造从v1到v3.1的"三线一单噪声修复"是真实的问题—修复—验证闭环。
