# DSH 与 Codex 任务路由

## DSH 直接处理

- 文件定位、参数提取和目录整理。
- CSV/JSON 统计、hash/manifest 检查。
- 正式版本核验和来源追踪。
- 按论文 3.2—3.5 整理已确认材料。
- 运行已有、确定性、不会改写正式结果的脚本。

执行前遵循项目根 `AGENTS.md` 的最小读取顺序。

## DSH 整理后交给 Codex

- 跨多个脚本的复杂问题。
- 无法由 Source of Truth 优先级解决的版本冲突。
- 实验逻辑核验和复杂调试。

先用 `codex-handoff` 生成最小交接包。默认展示给用户并等待确认，不自动调用 Codex。

## Codex 优先处理

- 修改正式实验设计或核心实验脚本。
- 改变统计方法。
- 重新构建正式评价集。
- 对科研结论作需要专业判断的解释或修改。

未获得明确修改授权时，Codex 也保持只读诊断。

## 升级判断

满足任一条件即停止 DSH 自主修改并升级：

1. 需要改变冻结产物或正式结果；
2. 需要在多个合理科研方法中作选择；
3. 冲突会改变论文方法、结果或结论；
4. 修改跨越多个核心脚本且影响不可由局部测试覆盖；
5. 用户明确要求 Codex。

## 降级行为

Codex 不可用或额度不足时，DSH 可继续确定性定位、提取、统计、核验和既有脚本运行；不得自行修改科研结论、实验设计、统计方法、正式评价集或正式结果。输出事实包并将待判断项标记 `UNRESOLVED`。
