## 一、我是谁，在做什么

我是一名环境工程方向的研究生，正在做**环评报告 AI 审核**方向的论文。具体来说，就是研究大语言模型（LLM）配上检索增强生成（RAG）之后，能不能自动审核环境影响评价报告中的错误。

**我的核心研究问题**：
1. RAG 在环评审核领域到底有没有用？
2. 不同能力的模型，从 RAG 中获益一样吗？
3. 不同质量的知识（通用搜索 vs 专业知识库），效果差多少？
4. 什么类型的审核题 RAG 帮助最大？

**论文目标**：发一篇中文核心期刊小论文（或 SCI 三区/四区）。

## 二、之前做了什么，为什么要重做（重要背景）

### 2.1 第一轮实验：ABCD 四组对比（已完成）

**实验设计**：
- 评价集：21 道题（后来扩充到 paired_48）
- 模型：DeepSeek v3（单模型）
- 四组条件：
  - **A 组**：纯模型基线（只有报告内容 + 简单提示词）
  - **B 组**：提示词优化（系统提示词 + 审核流程引导）
  - **C 组**：提示词 + Skill 架构（15 个审核 Skill 模块，包含审核流程、判定标准、输出格式等完整审核逻辑）
  - **D 组**：提示词 + Skill + RAG（在 C 组基础上加上 81 源知识库检索）

**发现的问题**：
- C 组（纯 Skill）相对于 B 组，**正确率没有提升，甚至部分题有所下降**——Skill 架构产生了**负效应**
- 导师指出：**这个设计不合理**，因为 Skill 里混合了太多东西（审核流程、输出格式、判定标准、知识内容），是一个"黑箱"，你根本不知道效果是从哪来的
- D 组（Skill+RAG）比 C 组有提升，但你说不清是 RAG 起作用了，还是 Skill 和 RAG 叠加的复杂交互起作用了
- 只有一个模型，无法研究"模型能力 × 知识"的交互效应

### 2.2 导师的核心意见

导师的原话大意是：
1. **Skill 不是一个干净的知识变量**，它包含了流程引导、格式约束、思维链等非知识因素，不能用来检验"RAG 有没有用"
2. **实验设计太混杂**，四组之间变了太多东西，结论归因不清
3. 需要一个**更干净的设计**，把"知识"这个变量单独拎出来，其他因素都控制住
4. 只有一个模型太单薄，应该引入模型能力维度，看不同模型的差异

### 2.3 重新设计的核心思路

**把 Skill 架构完全拿掉**，纯化实验设计：
- ❌ 不再用 Skill（15 个模块的复杂架构）
- ✅ 只用"纯知识检索 + 上下文注入"这种最基本的 RAG 形式
- ✅ 把"知识来源"作为唯一变量（无知识 / 搜索 / 领域 RAG）
- ✅ 加入"模型能力"维度（弱 / 中 / 强）
- ✅ 系统分类题目类型（E×P 框架），研究任务异质性

**一句话总结为什么重做**：
> 之前的实验 Skill 架构太混杂，导师说不合理，没法干净地检验 RAG 的作用。现在重新设计，去掉 Skill 这个干扰因素，用 3×3 析因设计纯化知识变量，系统研究"模型能力 × 知识质量 × 任务类型"三者的交互。

### 2.4 重新设计后已有的资产
- **评价集候选**：~60 道题，覆盖排放标准、危废识别、废气收集、生活污水等多个审核点
- **金标准**：E0P1 和 E1P1 部分题目已完成人工核验（A 级，结论非黑即白，无歧义）
- **知识库**：81 源环评专业知识库（BM25 + 稠密向量混合检索，409 父块 / 3459 子块）
- **实验脚本**：成熟的 API 调用框架，支持重试、验证、hash 记录（从 A 组脚本改造）

## 三、我重新设计的实验：3×3 析因设计

### 3.1 设计概览

```
              弱模型 A1    中模型 A2    强模型 A3
            ┌──────────┬──────────┬──────────┐
无知识 K1   │  K1A1    │  K1A2    │  K1A3    │
            ├──────────┼──────────┼──────────┤
联网搜索 K2 │  K2A1    │  K2A2    │  K2A3    │
            ├──────────┼──────────┼──────────┤
领域 RAG K3 │  K3A1    │  K3A2    │  K3A3    │
            └──────────┴──────────┴──────────┘
```

两个自变量，各 3 个水平，共 9 种组合。

### 3.2 自变量 A：模型能力（3 水平）

| 水平 | 模型 | 说明 |
|------|------|------|
| A1 弱 | qwen3.8-flash | 入门级轻量模型 |
| A2 中 | qwen3.7-max | 上一代旗舰模型 |
| A3 强 | qwen3.8-max | 当前旗舰模型 |

**选择逻辑**：都是 Qwen 同系列，训练数据和架构一致，只有能力差异。用"上代旗舰"做中间档，能力梯度比"同代 plus"更大，更容易观察知识替代效应。

### 3.3 自变量 K：知识来源（3 水平）

| 水平 | 实现方式 | 说明 |
|------|---------|------|
| K1 无知识 | 纯模型 + 报告内容 | 基线，模型只能靠内置知识 |
| K2 联网搜索 | Serper.dev API，top-5 搜索结果摘要 | 通用知识，模拟真实搜索场景 |
| K3 领域 RAG | 81 源环评专业知识库，混合检索 | 专业结构化知识，最高质量 |

### 3.4 因变量（三层指标）

**第一层：结论正确率**
- 判断模型输出的 CORRECT/INCORRECT 结论与金标准是否一致
- 计算整体准确率、精确率、召回率、F1

**第二层：过程指标（按 EP 差异化）**
- E0P0：数据提取准确率 + 章节定位准确率
- E1P0：标准引用准确率 + 数值准确率
- E0P1：复算准确率 + 一致性检出率
- E1P1：场景识别准确率 + 知识引用准确率 + 推理完整性 + 最终判断准确率
- （权重初始设定，实验后校准）

**第三层：错误类型分析**
- 假阳性率（误报率）：金标 CORRECT 但模型判 INCORRECT
- 假阴性率（漏报率）：金标 INCORRECT 但模型判 CORRECT
- 错误环节：提取错误 / 计算错误 / 推理错误 / 知识错误 / 方法错误
- 幻觉检测：编造标准 / 编造数据 / 编造章节

## 四、E×P 任务分类框架

我把环评审核题按两个维度分成四类：

### 维度 E：知识依赖度
- **E0**：答案在报告内，不需要外部知识
  - 例：环保投资占比计算（报告里有投资数据，直接除就行）
  - 例：VOCs 总量一致性检查（报告不同章节的数据对不对得上）
- **E1**：需要外部标准/法规知识
  - 例：排放标准选取对不对（要查 GB 标准）
  - 例：危废类别识别对不对（要查危废名录）

### 维度 P：推理复杂度
- **P0**：直接提取/查找，不需要复杂推理
  - 例：查一个标准限值是多少
  - 例：报告里某个数据是多少
- **P1**：需要计算/推理/综合判断
  - 例：废气排风量核算（要用公式算）
  - 例：综合判断收集效率取值是否合理

### 四类任务

| | P0（直接找） | P1（要计算） |
|---|---|---|
| **E0（报告内有）** | **E0P0** 字段抽取 | **E0P1** 一致性复算 |
| **E1（要查法规）** | **E1P0** 标准查阅 | **E1P1** 综合推理 |

### 预期 RAG 增益排序（从大到小）
E1P0 > E1P1 > E0P1 > E0P0

## 六、预期结果（基于 pilot 经验和文献推测）

### 6.1 整体正确率（9 格）

| | K1 无知识 | K2 联网搜索 | K3 领域 RAG | RAG 增益 |
|---|---|---|---|---|
| A1 弱模型 | 45% | 60% (+15%) | 74% | **+29%** |
| A2 中模型 | 55% | 67% (+12%) | 79% | **+24%** |
| A3 强模型 | 70% | 75% (+5%) | 86% | **+16%** |

### 6.2 按 EP 分类的增益（强模型上）

| 题型 | K1 | K3 | 增益 |
|------|-----|-----|------|
| E0P0 | 85% | 88% | +3% |
| E1P0 | 55% | 88% | **+33%** |
| E0P1 | 65% | 70% | +5% |
| E1P1 | 55% | 83% | +28% |

### 6.3 关键数字
- 整体 RAG 增益：+22%（均值）
- 知识替代效应：弱模型增益 - 强模型增益 = +13 个百分点
- 强模型 E1P0 增益：+33%（不可替代性的核心证据）
- K3-K2 差值（强模型）：11%（领域知识独有价值）

## 七、三个创新点

1. **I1：知识替代的领域边界**
   - 通用领域说"模型越强越不需要 RAG"，但在环评专业法规领域，即使最强模型在标准查阅题上仍有 33% 的提升
   - 说明专业法规知识是模型内置知识覆盖不了的长尾知识

2. **I2：弱模型缺量、强模型缺专**
   - 弱模型：K2（搜索）和 K3（领域 RAG）增益差不多，有知识就行
   - 强模型：K2 增益很小（+5%），K3 增益大（+16%），必须是专业高质量知识才有用
   - 知识质量对强模型更重要

3. **I3：E×P 任务异质性框架**
   - 提出"知识依赖度 × 推理复杂度"二维分类框架
   - E 维度决定 RAG 增益大小，P 维度决定模型间差异
   - 可以迁移到其他专业审核领域（法律审核、医疗审核等）

## 九、我担心的问题

1. **去掉 Skill 之后，实验会不会太简单了？** 纯 RAG（知识检索+上下文注入）是不是不够"高级"，发论文会不会显得单薄？
2. **16 题 pilot 是不是太少了？** 统计效力够不够？
3. **qwen3.7-max 作为中模型合不合理？** 因为 API 里没有 qwen3.8-plus，只能用上一代旗舰
4. **K2（搜索 API）的效果会不会太好/太差？** 不好控制中间水平的位置
5. **EP 分类框架会不会太简单？** 有没有更重要的维度没考虑到？
6. **temperature=0 会不会影响结果的普遍性？** 真实场景下不会用 0
7. **三个创新点够不够支撑一篇论文？** 哪个最站得住脚？哪个最弱？
8. **有没有什么混淆变量我没控制？** 比如 prompt 长度差异、检索时间等
9. **结果不理想怎么办？** 比如强模型 RAG 增益很小，我还能写什么？
10. **新旧实验的关系怎么处理？** 之前的 ABCD 四组数据还能用吗？论文里要不要写？怎么写？
11. **去掉 Skill 会不会反而让研究的"工程价值"降低了？** 毕竟真实系统里肯定要做流程设计的
