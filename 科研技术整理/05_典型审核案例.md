# 05 典型审核案例

> 生成日期：2026-08-26
> 案例来源：全部取自48题正式实验的真实题目与四组真实回答（`09_机制分析准备_20260822/06_典型题ABCD对照.md`，2026-08-22）。

## 案例A：RAG价值明显——设计风量"8.5%余量"陷阱

**题目**：PL007_DesignAirflow_Q01（废气设计风量审核，金属制品项目）

| 环节 | 真实内容 |
|---|---|
| 报告原文 | 21个集气管道×828 m³/h=17388 m³/h；打样间52.5 m³×20次/h=1050 m³/h；理论合计**18438 m³/h**；设计风量**20000 m³/h**（余量约8.47%）；排气筒DA001内径0.8m、高30m |
| 审核问题 | 废气设计风量取值是否合理 |
| Gold（人工确认） | **不合理，设计余量偏小**：知识库规定设计风量=各支管风量之和×(1+漏风系数)，漏风系数一般取10%~20%；按最低10%复算至少约20282 m³/h，20000 m³/h未达最低设计余量 |
| 普通LLM的问题 | A组（纯模型）判"**合理**"——它复算理论风量完全正确、也指出了"余量约8.47%"，但**不知道10%~20%漏风系数这条规范要求**，judge评语："虽正确复算理论风量并指出余量8.5%，但未识别该余量低于规范最低要求，导致关键审核结论错误。"（3/6） |
| RAG提供Evidence | B组Top-5证据命中：`#18 废气收集风量与设计风量核算指南`（漏风系数10%~20%）、`#30 废气收集形式与排风量计算审核指南`、`#17 废气收集形式及排气量计算指南`、HJ 2026-2013口径（吸附治理设计风量宜按最大废气排放量120%设计→约22126 m³/h），另核验活性炭过滤风速0.69 m/s<1.20 m/s、排气筒30m≥15m |
| Skill规定Procedure | review-eia-exhaust-design-airflow：触发于"漏风、同时工作、管网和风机设计风量"；程序要求先建立风量核算链，再逐项比较外部依据 |
| 最终审核结论 | B组（6/6）判"**存在问题**"：20000 m³/h低于10%漏风余量对应值20282 m³/h、低于120%口径22126 m³/h；建议提高设计风量或提供低于10%漏风仍可运行的设计依据 |
| 四组数字 | A=3/6，B=6/6，C=2/6，D=5/6；**B−A=+3**；C组（仅Skill）也判"合理"——没有证据锚，程序复算只能确认内部算术自洽 |

**参观者一句话**：同一个模型，复算能力完全一样，差的是"知不知道漏风系数要留10%"——这条知识在法规库里，不在模型脑子里。

## 案例B：Skill价值明显——建设内容完整性的"字段化搜查"

**题目**：PL011_Construction_Q01（工程分析内容完整性审核，固化剂生产项目）

| 环节 | 真实内容 |
|---|---|
| 报告原文 | 固化剂生产1500 t/a（关键设备最大产能2080 t/a），设置工程组成、产品产能、设备、原辅材料、用排水、工作制度等章节，工艺为投料—搅拌—加热—过滤/包装—设备清洗 |
| 审核问题 | 建设项目工程分析内容是否齐全（能否支撑后续产污分析） |
| Gold（人工确认） | **齐全，无明显缺漏**：已形成"产品—原辅材料—设备—工艺—产污环节"闭合链条 |
| 普通LLM的问题 | B组（RAG）反而**4/6**：判"正确"（结论方向对）但judge评语"**遗漏润滑油缺失、分装工序不清等实质性问题，完整性判断过度乐观**"——RAG检索到的编制指南对此题无有效约束（该题快照评级即2B：缺#31编制内容完整性清单），证据到了却不会"搜查"报告 |
| Skill规定Procedure | review-eia-construction-content-completeness：触发于"工程组成、产品、原料、设施、工艺和产污环节"；**字段化证据抽取**（C组实际抽取12条报告证据、执行7项核查，A组仅6条/5项），程序要求逐字段核对交叉章节一致性 |
| Skill抓出的真实问题 | ①固废章节引用"年用润滑油0.05 t/a并产生废润滑油"，但**原辅材料清单没列润滑油**（清单与产污分析不闭合）；②清洗用苯甲醇48 t/a与表2-3苯甲醇年用量300.6306 t/a的**包含关系未说明**（物料平衡悬空）；③工艺流程有"分装"工序，**设备清单却无分装/灌装设备**，且未说明分装是否产污 |
| D组进一步发现 | 原料包装桶属性前后矛盾（表2-9"供应商回收利用" vs 后文"HW49危险废物委托处置"）；平面布置图引用编号与目录不一致 |
| 最终审核结论 | C组、D组均6/6："部分完成"（主体闭合+局部缺漏需补充澄清），发现的问题数量与深度随程序约束递增 |
| 四组数字 | A=6/6，B=4/6，C=6/6，D=6/6；**B−A=−2（RAG在此类内部逻辑任务上反而干扰），D−B=+2**，interaction=+2 |

**参观者一句话**：完整性审核不缺法规、缺"逐字段搜查+跨章节对账"的流程——Skill把专家的检查清单变成程序，机器才会去翻"固废章节引用了原辅材料清单里没有的润滑油"。

## 案例C：RAG+Skill协同明显——公报引用"一字之差"漏检

**题目**：PL006_EnvQuality_Q01（环境质量现状数据引用审核）——**全数据集交互效应最高的题目（+3）**

| 环节 | 真实内容 |
|---|---|
| 报告原文 | 大气：引用《2022年度佛山市顺德区环境质量状况公报》（报告写法），SO2/NO2/PM10/PM2.5/CO/O3六项数值列出，O3=190 μg/m³超二级限值160，判定不达标区；地表水：顺德支流执行III类，尾水经杏坛污水处理厂排入 |
| 审核问题 | 环境质量现状引用数据是否准确 |
| Gold（人工确认） | 数据**实质正确**（数值与公报一致），但存在引用形式错误：公报名称误写"环境质量状况公报"（正确为"**生态**环境状况公报"，缺"生态"二字）、文号误写"佛顺环函〔2023〕26号"（正确"佛**环**顺函〔2023〕26号"）；截至审核日最新公报为2024年度 |
| 普通LLM的问题 | A组（4/6）正确怀疑了地表水证据链不足，**但未发现公报名称及文号笔误**——这类"一字之差"不在数据层面，模型不会自发逐字核对引用格式 |
| RAG单独的问题 | B组（RAG，仅3/6）：用公报原文把六项污染物数值、GB3095/GB3838限值、O3占标率复算**全部验证一致**——然后判"**正确**"。judge评语："利用RAG验证了数据数值准确性，但**完全遗漏参考答案强调的公报名称及文号笔误问题，审核结论过度乐观**" |
| Skill单独的问题 | C组（仅Skill，4/6）：工作流完整（6条证据、9项核查项）、发现了地表水证据缺口，但"受限于无RAG未能核实外部数据及形式错误，审核未闭环"，判"部分完成" |
| 协同机制 | Skill（review-eia-environmental-quality-data：触发于"公报、年份、原文数据和时效性"）规定**逐项核对引用名称/文号/年份**的程序；RAG提供公报原文作为核对材料——B组不是没有证据，是没有用证据做形式核对的程序；C组不是没有程序，是没有可核对的原文 |
| 最终审核结论 | D组**6/6**："存在问题"——既确认数据实质准确（数值、限值、达标判定全部与公报一致），又精准指出公报名称缺"生态"、文号"佛顺环函"应为"佛环顺函"两处笔误，并补充表3-1文本解析粘连风险，与Gold高度一致 |
| 四组数字 | A=4/6，B=3/6，C=4/6，**D=6/6**；D−B=+3，D−C=+2，**interaction=+3（48题最高）**；四组外部证据引用数：A=0、B=4、C=0、D=4 |

**参观者一句话**：RAG给了"标准答案的原文"，Skill给了"逐字核对的动作"，两个加起来才能抓住"生态"两个字丢了这种机器最容易放过、人工专家一定会抓的错误。

## 案例D（边界案例）：Skill的保守边界——收集效率90%被误降级

**题目**：PL006_CaptureEfficiency_Q01（废气收集效率取值审核）——用于说明**Skill单独使用的真实代价**，展览讲"边界条件"时使用。

| 环节 | 真实内容 |
|---|---|
| 报告原文 | 喷纳米油、烘干、清洗喷枪等工序设于密闭喷漆线/喷房，整室负压抽风，换气12次/h、设计风量18000 m³/h（理论约15000 m³/h）；收集效率统一取**90%**，依据为报告自引《广东省工业源VOCs减排量核算方法（2023年修订版）》"单层密闭负压最高可达90%" |
| Gold（人工确认） | **合理**：知识库"单层密闭负压"参考值95%，审核规则要求实际取值不得高于对应收集方式上限；报告取90%<95%，与密闭负压形式匹配 |
| A组（纯模型） | **6/6 判"正确"**：judge评语"在无RAG条件下准确提取报告证据并验证风量逻辑，边界说明清晰，符合无外部依据时的最佳实践" |
| C组（仅Skill） | **4/6 判"部分完成"**：内部核查详尽，但因无法核验2023核算方法的适用条件，把结论降级。judge评语："**判定为'部分完成'过于保守**；虽体现完整工作流，但未能在无RAG时基于报告自证给出确定性合理结论" |
| D组（RAG+Skill） | 5/6：用RAG核实95%上限、确认90%未超限（方向正确），同时发现报告表述"单层密闭负压最高90%"与RAG的95%**不一致**——但结论表述仍保留"部分完成"（judge："核心结论置信度不足"） |
| 四组数字 | A=6/6，B=6/6，C=4/6，D=5/6；C−A=−2 |

**参观者一句话**：程序要求"外部依据可追溯才下结论"，没有RAG时程序诚实地走向保守——这不是bug，是"宁可转人工也不乱判"的审核纪律，也正是48题统计中C组下降、D组恢复的微观机制。
