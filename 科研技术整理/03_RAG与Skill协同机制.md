# 03 RAG 与 Skill 协同机制

> 生成日期：2026-08-26
> 统计口径：48题×4=192条配对回答的2×2析因统计（`08_2x2析因统计_48题_20260822/12_report/statistical_report.md`，2026-08-22冻结，PRIMARY=common_3d_score 0–6）。
> 案例口径：`09_机制分析准备_20260822/06_典型题ABCD对照.md`（48题正式评分衍生的20道典型题客观记录）。

---

## 主线

```
RAG  = 给模型正确的法规与专业依据（知识约束：Evidence）
Skill = 规定模型应该如何使用这些依据完成审核（程序约束：Procedure）
LLM  = 在 Evidence 和 Procedure 双重约束下完成推理（Reasoning）
```

三者分工不是概念设计，而是**架构层强制**：每个Skill第0节声明"本Skill是审核程序，不是法规知识副本"，具体条款、限值、版本必须由运行时`rag_evidence`提供；总路由器声明"路由负责选择，专业Skill负责判断，RAG负责提供外部依据"——三层职责在文件层面互相隔离。

---

## 1. 统计证据：三效应与性质判定

48题配对析因（题级contrast+配对bootstrap 10,000次，MixedLM交叉验证一致；来源：statistical_report.md §3–§4）：

| 效应 | 估计(0–6) | bootstrap 95% CI | 结论 |
|---|---|---|---|
| RAG main | +0.115 | [-0.094, 0.344] 跨0 | 不显著 |
| Skill main | **-0.219** | [-0.396, -0.042] 不跨0 | **显著为负**（dz=-0.34） |
| RAG×Skill interaction | **+0.396** | [0.167, 0.625] 不跨0 | **显著为正**（dz=0.48，p=0.0016） |

简单效应（题内配对）：

| 简单效应 | 估计 | 95% CI | 含义 |
|---|---|---|---|
| B−A（RAG单独） | -0.083 | 跨0 | RAG单独无总体增益 |
| C−A（Skill单独） | **-0.417** | 不跨0 | Skill单独显著受损 |
| D−C（Skill在场时加RAG） | **+0.313** | [0.083, 0.563] 不跨0 | RAG显著修复Skill |
| D−B（RAG在场时加Skill） | -0.021 | 跨0 | Skill叠加在RAG上无总体增益 |
| D−A（联合 vs 基线） | -0.104 | 跨0 | **D未显著超越A** |

**性质判定（必须完整表述，禁止简化成"1+1>2"）**：这是**补偿型正向交互**，不是增益型协同——Skill单独引入造成-0.417的损失，RAG在Skill存在时提供+0.313恢复，使D组（91.32%）回到与基线A组（93.06%）统计相当的水平。统计报告原文："该正向交互不是'1+1>2'的增益型协同（D未超过A），而是补偿型正向交互：Skill单独引入造成-0.417的correctness相关损失，RAG在Skill存在时提供+0.313恢复，使D回到与baseline A统计相当的水平。"（§8）

## 2. 机制：为什么Skill需要RAG锚定

judge rationale的定性机制观察（statistical_report.md §7，exploratory）：

> C组correctness低于A组的12题中，**11题**rationale指向同一模式——Skill分步核查工作流在**无RAG外部证据支撑时诱导过度保守判定**（将金标认定"合理/无误"的结论降级为"部分完成/存在问题"，即过度挑错）。这12题中**11题在加RAG后（D组）correctness恢复**。

典型案例（PL006_CaptureEfficiency_Q01，`06_典型题ABCD对照.md` §C）：
- 题目：喷漆线整室密闭负压，报告取收集效率90%。Gold：合理（知识库"单层密闭负压"上限95%，90%未超上限）。
- A组（裸模型）6/6："结论正确且理由充分；在无RAG条件下准确提取报告证据并验证风量逻辑"；
- C组（仅Skill）4/6：内部核查详尽，但因无法核验《广东省工业源VOCs减排量核算方法》90%对应关系，把结论降级为"部分完成"——judge评语："**判定为'部分完成'过于保守**；虽体现完整工作流，但未能在无RAG时基于报告自证给出确定性合理结论"。

**机制表达**：Skill工作流要求"外部依据可追溯才能下确定结论"；没有RAG时，程序诚实地走向"无法判断/部分完成"——程序约束没有错，缺的是知识约束提供的锚。RAG补上锚之后，同一套程序产出正确结论。

反向维度证据（同报告§7）：RAG组法规维度稳定（regulatory_basis：B=1.848、D=1.851，D−B=0.000），Skill维度D组满分（skill_workflow：C=1.938 → D=2.000，边缘提升p=0.083）——**B/D组的法规依据表现和C/D组的流程执行表现分别证明两个因子各自"到位"**。

## 3. 任务依赖性：谁在什么任务上有效（不挑正面结果）

14个冻结task_type的异质性（statistical_report.md §5，小样本类别仅作模式观察）：

| 模式 | 任务类别 | 证据（0–6尺度） |
|---|---|---|
| **RAG受益明显** | 水污排放（RAG main +1.000，交互0）；设计风量/环境质量（RAG main +0.833）；产污系数（+0.500） | 外部参数/版本敏感任务 |
| **Skill单独受损** | 收集效率（Skill main -0.875）；噪声排放（-0.750） | 需外部依据才能下确定结论的任务 |
| **正向交互集中** | 产污系数/环境质量（interaction +1.000）；固废（+0.800）；建设内容（+0.750）；收集风量（+0.600） | 知识核验型任务 |
| **负交互（唯一）** | V01行业分类/投资核算（interaction -0.400） | 报告内部逻辑+常识判断任务，外部检索与流程约束均无增益 |
| **零交互** | 水污/噪声（interaction 0）；活性炭/危废/大气（0，天花板） | — |

post-hoc二分视角（标注为探索性，n=23 vs 25）：知识密集型任务 interaction **+0.478 [0.19, 0.77]** 显著、Skill main -0.370显著；程序核查型任务三效应均不显著（interaction +0.320 [-0.07, 0.71]）。

**维度分解**（§6）：交互增益由 correctness（+0.188 [0.04, 0.33]）与 actionability（+0.208 [0.08, 0.35]）承载；Skill单独的负效应集中于 correctness（-0.156）；evidence_use 四组均近满分（1.96–1.98），**无区分度（天花板）——不能拿evidence_use宣传任何因子的优势**。

## 4. 案例级证据：三种协同形态

### 形态一：RAG主导（Skill作用小）——PL007_DesignAirflow_Q01

设计风量题（理论风量18438 m³/h，设计风量20000 m³/h，余量8.5%）：
- A组判"合理"（错）——不知道"漏风系数一般取10%~20%"的规范要求；
- B组（RAG）6/6 判"存在问题"——用知识库漏风系数10%复算出最低20282 m³/h，并引用HJ 2026-2013的120%口径；
- C组（Skill）仍判"合理"（2/6）——只有内部算术复算能力，judge评语："仅验证了内部算术一致性，未利用Skill核查设计余量合规性，遗漏关键审核点"；
- D组5/6。B−A=+3，D−B=−1，**interaction=0**。
- 结论：**知识可检索、判断规则单一的任务，RAG单独即完成主要工作，Skill流程不增加判别力**。

### 形态二：协同闭环（最高交互题）——PL006_EnvQuality_Q01

环境质量公报引用题（Gold：数据正确，但公报名称误写"环境质量状况公报"（缺"生态"）、文号误写"佛顺环函"（正确"佛环顺函"））：
- A组4/6：正确怀疑地表水证据链不足，**但未发现公报名称及文号笔误**；
- B组（RAG）3/6：用RAG验证了六项污染物数值与GB3095/GB3838限值全部一致——**却判"正确"，完全遗漏笔误**，judge评语："利用RAG验证了数据数值准确性，但完全遗漏参考答案强调的公报名称及文号笔误问题，**审核结论过度乐观**"；
- C组（Skill）4/6：工作流完整、发现地表水证据缺口，但"受限于无RAG未能核实外部数据及形式错误，审核未闭环"；
- D组**6/6**：既用RAG确认数据实质准确，又精准指出公报名称及文号笔误，与Gold高度一致。B−A=−1，D−B=+3，**interaction=+3（全数据集最高）**。
- 结论：**RAG给了核对材料，Skill给了"逐项核对引用形式"的检查程序；缺任何一半，笔误都漏检**——B组不是没有证据，是没有使用证据做形式核对的程序。

### 形态三：RAG在内部逻辑任务上反而干扰——PL011_Construction_Q01

建设内容完整性题（Gold：齐全，无明显缺漏）：
- A组6/6：发现润滑油未列入原辅材料、分装工序未细化等真实缺漏（按评分规则"额外真实问题不扣分"）；
- B组（RAG）**4/6**：判"正确"但"遗漏润滑油缺失、分装工序不清等实质性问题，完整性判断过度乐观"——B−A=−2；
- C组（Skill）6/6：12条报告证据、7项核查项，发现润滑油/苯甲醇包含关系/分装设备三类缺漏，judge评语："体现了完整的分步核查流程"；
- D组6/6：进一步发现包装桶属性前后矛盾（表2-9供应商回收 vs 后文HW49危废）、图纸引用编号错误——D−B=+2，**interaction=+2**。
- 结论：**内部逻辑核查任务上RAG单独无增益甚至引入干扰（检索到的编制指南未提供有效约束），Skill的证据字段化抽取与分步核查才是主力；二者合一时程序+证据产出最深发现**。

### 边界形态：两者都不该用——V01类任务

V01（行业分类/投资核算）是唯一负交互类别（-0.400）：此类任务依赖报告内部逻辑与常识判断，外部检索与流程约束均无增益（statistical_report.md §5模式4）。工程含义：**接入时应做任务分层，而不是全量套用RAG+Skill**。

## 5. 冗余、冲突与真实边界（汇总表）

| 关系类型 | 证据 | 展览表述建议 |
|---|---|---|
| RAG有效、Skill作用小 | 设计风量/水污（RAG main +0.833/+1.000，交互0）；PL007案例 | 如实说明"参数核验类任务检索即答案" |
| Skill有效、RAG干扰 | 建设内容（RAG main -0.375）；PL011案例B−A=−2 | 说明"内部逻辑任务不需要外部检索" |
| 协同（补偿型） | 总体interaction +0.396显著；知识密集子集+0.478；PL006案例 | 主表达：**"Skill规定程序，RAG提供锚点，缺一则程序退化为保守或证据退化为乐观"** |
| 冗余 | D−B=-0.021不显著；evidence_use四组天花板 | 不得宣称"Skill叠加RAG再提升" |
| 冲突（负交互） | V01类-0.400 | 任务分层接入的依据 |
| 未定 | D−A=-0.104不显著（D未超越A）；天花板效应压缩效应空间 | 承认联合系统与强基线打平，增益体现在错误模式的结构（幻觉↓、保守↓）而非总分 |

## 6. 面向展览的协同一句话表达

> 在48题×4组配对实验中，RAG与Skill呈现统计显著的**补偿型正向交互**（+0.396，95% CI [0.167, 0.625]）：Skill把审核流程程序化后，模型在没有法规依据时倾向"无法判断"的过度保守（C组较基线-0.417）；RAG恰好为每一步程序提供可追溯的证据锚点，使D组恢复到与基线相当（D−C=+0.313）——**知识约束与程序约束缺一不可，这正是"AI环评既要有依据、又要有流程"的实验证明**。
