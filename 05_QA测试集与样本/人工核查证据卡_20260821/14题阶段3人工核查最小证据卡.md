# 国民经济行业分类审核

## 1. Skill结构

本Skill覆盖环评报告中"一、建设项目基础情况"→"国民经济行业类别"的审核，依据产品、原料、工艺和用途判定行业分类是否正确。

```text
01 国民经济行业分类审核
├─ A 信息提取（产品、原料、工艺、填报类别）
├─ B 项目概述总结
├─ C 行业分类匹配
├─ D 比对与结论
└─ E 输出结论
```

## 2. 输入

```json
{
  "question_id": "",
  "question": "",
  "report_context": "",
  "reference_mode": "embedded_verified_classification"
}
```

报告上下文不得包含Word批注、修订痕迹和人工修改意见。

## 3. 审核总流程

### 第一步：信息提取

从报告以下位置提取四类关键信息：

| 序号 | 提取内容 | 提取位置 | 说明 |
|------|----------|----------|------|
| ① | 产品名称、产品备注 | "二、建设项目工程分析"→表2-2"项目主要产品产能一览表" | 提取所有产品的名称、产能、单位和备注 |
| ② | 主要原辅材料 | "二、建设项目工程分析"→表2-7"原料材料年用量一览表" | 提取所有物料名称 |
| ③ | 生产工艺 | "二、建设项目工程分析"→"工艺流程简述" | 总结项目设计的核心生产工艺 |
| ④ | 填报行业类别 | "一、建设项目基础情况"→"国民经济行业类别" | 提取项目编写的行业代码和名称 |

提取时需注意：
- 产品名称应提取"最终对外产品"，不是中间物料或边角料；
- 原料名称应提取"主要基材"，如树脂颗粒、原纸、外购薄膜等；
- 工艺应提取"决定产品材料形态、功能或用途的关键加工"，不是包装、搬运等末端动作；
- 填报类别需同时提取代码和名称（如C2929塑料零件及其他塑料制品制造）。

### 第二步：项目概述总结

根据提取的信息，总结形成项目概述，使用固定句式：

> 使用xxx原料，通过xxx工序，生产用于xxx的xxx产品。

举例：
- 使用塑料粒，通过注塑成型，生产用于家用电器配件、日用品配件的注塑配件。
- 使用PE塑料粒，通过吹膜工艺，生产用于不锈钢保护膜的塑料薄膜。
- 使用SEBS和增粘树脂，通过混料、双螺杆挤出、水下切粒，生产用于改性塑料的SEBS塑料粒料。

若一句话中出现两个互不依赖的最终产品，拆成两条活动分别总结。

### 第三步：行业分类匹配

根据项目概述，从《2017年国民经济行业分类注释》（GB/T 4754-2017，按第1号修改单修订）中匹配相符的国民经济行业类型。

匹配方法：
1. 按最终产品名称查询分类注释中的大、中、小类解释；
2. 核对小类的"指……"定义及"包括""不包括"项；
3. 检查近邻小类，做排除判断；
4. 由小类向上检查中类、大类、门类，防止名称相似但经济活动性质不同。

**有内置分类注释时**：使用`scripts/search_industry_classification.py`检索，或直接查询`references/2017国民经济行业分类注释_按第1号修改单修订.xlsx`。

**无内置分类注释时（参数知识辅助判断）**：可使用模型预训练中获得的国民经济行业分类知识（如C2929对应"其他塑料制品制造"、C2921对应"塑料薄膜制造"等），做初步判断，但必须：
- 在`external_validation_result.status`中标注`parameter_estimated`；
- 在`scope_note`中说明"分类基于模型参数知识，未经外部分类注释原文核验"；
- 不得将参数知识结论等同于已验证结论。

### 第四步：比对与结论

将识别判定的行业类别与项目填报的行业类别进行比对：

| 比对结果 | 判定结论 | 条件 |
|----------|----------|------|
| 代码与名称完全一致 | 正确 | 产品—工艺—用途与分类注释相符，且与填报一致 |
| 代码或名称不一致 | 需复核 | 写明识别类别、填报类别和具体差异 |
| 关键证据缺失 | 需复核 | 写明缺少产品、工艺、用途或分类依据中的哪一项 |

**禁止将"无内置分类注释"等同于"无法判断"。** 无内置注释时，应完成内部审核并用参数知识做初步判断。

### 第五步：输出结论

按照以下格式输出最终结论：

```text
1、国民经济行业类型判定结论：正确/需复核；
2、具体分析：根据项目概况，本项目主要通过xxx生产工艺，生产xxxx产品，经识别判定国民经济行业Cxxxx（小类编号+行业类别名称），与项目填报的国民经济行业类别Cxxxx（小类编号+行业类别名称）一致/有差异需要复核确认。
```

举例：
```text
1、国民经济行业类型判定结论：正确；
2、具体分析：根据项目概况，本项目主要通过注塑成型、铣床、磨床、火花机加工等生产工艺，生产家用电器、日常用品的注塑配件以及注塑用的注塑模具，经识别判定国民经济行业为C2929塑料零件及其他塑料制品制造、C3525模具制造，与项目填报内容一致。
```

## 4. 统一双层结论

### 第一层：报告内部审核

输出`report_internal_result`，包含：

- `status`：`pass`（内部一致无矛盾）| `issue_found`（发现内部矛盾）| `partially_verified`（部分可核验）| `insufficient_report_evidence`（报告关键证据缺失）；
- `evidence`：从报告中提取的产品、原料、工艺、填报类别等证据；
- `checks`：逐项判定结果；
- `issues`：具体问题描述。

### 第二层：外部分类核验

输出`external_validation_result`，包含：

- `status`：
  - `verified`：有内置分类注释且已逐项核验；
  - `parameter_estimated`：无内置分类注释，使用参数知识做初步判断，未经外部原文核验；
  - `not_required`：纯内部审核题；
  - `insufficient_reference`：有分类注释但关键条目缺失；
  - `not_performed`：既无分类注释也无法用参数知识判断。
- `conclusion`：核验结论；
- `references_used`：使用的参考资料；
- `missing_references`：缺失的参考资料。

### 最终结论

`final_answer.judgement`：

- **正确**：内部审核通过且分类核验确认（或参数知识判断一致）；

# 环境质量现状数据审核

## 1. Skill结构

本Skill覆盖环评报告中"三、区域环境质量现状、环境保护目标及评价标准"章节的大气和地表水环境质量现状数据引用审核。

```text
05 环境质量现状数据审核
├─ A 大气环境质量现状审核
└─ B 地表水环境质量现状审核
```

## 2. 输入

```json
{
  "question_id": "",
  "question": "",
  "report_context": "",
  "reference_bundle": []
}
```

`reference_bundle`为空时，仍执行报告内部审核，并可使用模型参数知识做初步判断。

## 3. 审核总流程

### 第一步：提取

从报告"三、区域环境质量现状、环境保护目标及评价标准"章节中提取：

**大气环境部分：**
1. 项目所在地所属大气功能区类型；
2. 所引用的环境状况公报名称及年份；
3. 大气环境现状分析描述内容（整段内容）；
4. 大气污染物浓度数据表格（污染物名称、浓度值、占标率、变化率、达标状态）。

**地表水环境部分：**
1. 项目污水排入的污水处理厂名称、尾水排放的河道名称；
2. 所引用的环境状况公报名称及年份；
3. 地表水环境现状分析描述内容（整段内容）；
4. 地表水水质数据表格（断面名称、水质类别、达标情况）。

### 第二步：近3年有效性判断

判断报告中引用的环境状况公报年份是否属于**近3年**（以报告编制日期为基准往前推3个年度）。

- 若报告编制日期为2024年，则近3年指2021年度、2022年度、2023年度的公报；
- 若引用公报超出近3年范围，应在结论中标注"未使用近3年数据"。

### 第三步：报告内部审核

对提取内容执行内部一致性检查（详见A、B子流程）。

### 第四步：公报对比（有RAG时）

有`reference_bundle`时，将报告引用的数据与公报原文逐项对比：
- 公报名称、年份和发布单位是否一致；
- 污染物数值、单位、变化率是否与公报原文一致；
- 水体、断面名称和水质类别是否一致；
- 报告编制时点可获得的近三年数据是否完整。

### 第五步：新公报提示

检索知识库中该地区（如顺德区）最新年份的公报情况，与环评引用的对比，判断是否有可用的新公报。若有，在结论中做出提示："经检索该地区最新的环境状况公报为《xxxxx》，可供参考"。

### 第六步：参数知识辅助判断（无RAG时）

无`reference_bundle`时，可使用模型预训练中获得的参数知识（如公报名称、发布年份、顺德区环境质量概况）做**初步判断**，但必须：
- 在`external_validation_result.status`中标注`parameter_estimated`；
- 在`scope_note`中说明"限值基于模型参数知识，未经外部公报原文核验"；
- 不得将参数知识结论等同于已验证结论。

## 4. A：大气环境质量现状审核

### 提取

从报告"三、区域环境质量现状、环境保护目标及评价标准"→"大气环境"中提取：

1. 项目所在地所属大气功能区类型（如二类区）；
2. 所引用的环境状况公报名称及年份（如《2022年度佛山市顺德区环境质量状况公报》）；
3. 大气环境现状分析描述内容（整段文字）；
4. 大气污染物浓度数据表（表头、污染物、浓度值、占标率、变化率、达标状态）。

### 判定内容

| 序号 | 判定项 | 判定方法 |
|------|--------|----------|
| ① | 公报年份有效性 | 判断引用公报是否为近3年数据 |
| ② | 公报名称一致性 | 检查报告各章节引用的公报名称、文号是否统一 |
| ③ | 表格年份与标题一致性 | 检查表格标题标注的年份与数据列实际年份是否一致 |
| ④ | 污染物数值正确性 | 核对污染物浓度值、占标率计算是否正确（占标率=实测浓度/标准限值×100%） |
| ⑤ | 变化率正负号一致性 | 检查"上升/下降"描述与变化率数值正负号是否一致（浓度下降应为负值或标注"↓"） |
| ⑥ | 达标结论一致性 | 检查达标/不达标结论与表格数据是否一致（如O3超标则应判定为不达标区） |
| ⑦ | 公报数据对比（有RAG时） | 将报告数值与公报原文逐项对比 |

### 参数知识辅助（无RAG时）

无RAG时，可基于参数知识对以下内容做初步判断：
- 顺德区常用环境质量公报名称（如《2022年度佛山市顺德区环境质量状况公报》，文号佛环顺函〔2023〕26号）；
- 顺德区大气环境质量一般状况（如顺德区属环境空气功能区二类区，主要污染物为O3）；
- 标准限值参考（如GB3095-2012中二级标准：SO2≤60μg/m³、NO2≤40μg/m³、PM10≤70μg/m³、PM2.5≤35μg/m³、O3≤160μg/m³、CO≤4mg/m³）。

### 输出结论格式

- **正确**：公报年份有效、名称一致、数据与公报原文一致、达标结论正确；
- **存在问题**：发现年份错误、数据不一致、变化率正负号错误等；
- **部分完成**：内部审核完成但外部公报原文未核验（无RAG）。

## 5. B：地表水环境质量现状审核

### 提取

从报告"三、区域环境质量现状、环境保护目标及评价标准"→"地表水"中提取：

1. 项目污水排入的污水处理厂名称、尾水排放的河道名称；
2. 所引用的环境状况公报名称及年份；
3. 地表水环境现状分析描述内容（整段文字）；
4. 地表水水质数据表（断面名称、水质类别、评价标准、达标情况）。

### 判定内容

| 序号 | 判定项 | 判定方法 |
|------|--------|----------|
| ① | 公报年份有效性 | 判断引用公报是否为近3年数据 |
| ② | 公报名称一致性 | 检查报告各章节引用的公报名称、文号是否统一 |
| ③ | 排水去向一致性 | 检查污水处理厂名称、尾水河道在各章节是否表述一致 |
| ④ | 断面名称一致性 | 检查表格中断面名称与正文描述是否一致（注意"东海大河"vs"新涌大河"等差异） |
| ⑤ | 水质类别正确性 | 核对水质类别标注是否正确（如Ⅲ类、Ⅳ类） |
| ⑥ | 达标结论一致性 | 检查达标结论与水质类别数据是否一致 |
| ⑦ | 公报数据对比（有RAG时） | 将报告数值与公报原文逐项对比 |

### 参数知识辅助（无RAG时）

无RAG时，可基于参数知识对以下内容做初步判断：
- 顺德区常用环境质量公报名称及年份；
- 顺德区主要河道及断面（如顺德支流、桂畔海等）；
- 顺德区地表水环境质量一般状况（如主要水体水质达Ⅲ类标准）。

### 输出结论格式

- **正确**：公报年份有效、名称一致、排水去向一致、数据与公报原文一致；
- **存在问题**：发现断面名称不一致、水质类别错误、公报年份不统一等；
- **部分完成**：内部审核完成但外部公报原文未核验（无RAG）。

## 6. 统一双层结论

### 第一层：报告内部审核

输出`report_internal_result`，包含：

- `status`：`pass`（内部一致无矛盾）| `issue_found`（发现内部矛盾）| `partially_verified`（部分可核验）| `insufficient_report_evidence`（报告关键证据缺失）；
- `evidence`：从报告中提取的公报名称、年份、数据等证据；
- `checks`：逐项判定结果；
- `issues`：具体问题描述。

### 第二层：外部公报核验

输出`external_validation_result`，包含：

- `status`：
  - `verified`：有RAG且已逐项核验公报数据；
  - `parameter_estimated`：无RAG，使用参数知识做初步判断，未经外部原文核验；
  - `not_required`：纯内部审核题；
  - `insufficient_reference`：有RAG但关键公报缺失；
  - `not_performed`：既无RAG也无法用参数知识判断。
- `conclusion`：核验结论；
- `references_used`：使用的参考资料；
- `missing_references`：缺失的参考资料。

### 最终结论

`final_answer.judgement`：

- **正确**：内部审核通过且外部核验确认（或参数知识判断一致）；
- **存在问题**：内部审核发现矛盾或数据错误；
- **部分完成**：报告内部一致但外部公报原文未核验；
- **待人工复核**：报告关键证据缺失，无法完成判断。

### 最终分析输出格式

```text
1、大气及地表水环境质量引用数据正确（或xx环境质量引用数据不正确，未使用近3年数据 / 或xx环境现状分析有新的可用公报数据）；

2、项目大气环境质量引用xxxx环境质量公报（引用公报名称），环评对大气环境质量分析内容与环境状况公报中大气环境状况描述一致（或与xxx环境状况公报中大气环境状况描述不一致，正确内容应为：（对错误内容进行分析改正））（或与xxx环境状况公报中大气环境状况描述一致，经检索该地区最新的环境状况公报为《xxxxx》，可供参考）。

项目地表水环境质量引用xxxx环境质量公报（引用公报名称），环评对地表水环境质量分析内容与环境状况公报中地表水环境状况描述一致（或与xxx环境状况公报中地表水环境状况描述不一致，正确内容应为：（对错误内容进行分析改正））（或与xxx环境状况公报中地表水环境状况描述一致，经检索该地区最新的环境状况公报为《xxxxx》，可供参考）。
```

**禁止将"无RAG"等同于"无法判断"。** 无RAG时，应完成内部审核并用参数知识做初步判断，在`scope_note`中标注"参数知识初步判断，未经外部核验"。

## 7. 问题分级

| 等级 | 描述 | 示例 |
|------|------|------|
| 严重 | 数据实质错误 | 污染物浓度数值与公报不一致 |
| 中等 | 年份或对象错误 | 引用公报超出近3年、断面名称错配 |
| 轻微 | 表格与正文不一致 | 表格标题年份与数据列年份不匹配 |
| 轻微 | 变化率正负号错误 | PM10下降但变化率标注为正值 |
| 提示 | 新公报可用 | 经检索存在更新版本的公报 |

## 8. 禁止事项

- 不把报告自己引用的公报视为已经被外部验证（需独立核验）；
- 不因为公报缺失就整题拒答；
- 不硬编码任何测试项目答案；
- **允许使用模型参数知识做初步判断**，但必须标注`parameter_estimated`，不得等同于已验证结论；
- 不忽略年份不一致问题（近3年有效性是核心审核点）。

## 5. A：废水排放标准判定

### 提取

从报告"污染物排放控制标准"→"水污染物排放标准"中提取：

1. 生活污水预处理执行标准；
2. 排入的污水处理厂名称；
3. 尾水排放河道；
4. 尾水排放执行标准；
5. 排放执行标准表格的限值数据。

### 判定内容

| 序号 | 判定项 | 判定方法 |
|------|--------|----------|
| ① | 生活污水预处理排放标准是否正确 | 对比知识库或参数知识中该标准的适用范围和限值 |
| ② | 识别排入的污水处理厂名称 | 从报告各章节提取，判断是否一致 |
| ③ | 尾水排放河道是否正确 | 根据污水处理厂名称，判断尾水排放河道描述是否合理 |
| ④ | 尾水排放标准是否正确 | 对比知识库或参数知识中该标准的适用范围 |
| ⑤ | 排放标准表格限值数据 | 逐项核对表格中的CODcr、BOD5、NH3-N、SS等限值数值 |

### 输出结论格式

- **无误**：生活污水排放标准、污水处理厂名称、尾水河道、尾水标准、表格限值均正确；
- **存在缺漏**：缺少某项内容（如未提及尾水标准）；
- **存在错误**：某项内容有误（如标准限值填写错误、河道名称错误）。

## 6. B：大气排放标准判定

### 提取

1. 从"二、建设项目工程分析"→"项目各工序产污情况一览表"提取废气产污环节、污染源名称和主要污染物；
2. 从"二、建设项目工程分析"→"主要原辅材料及能源消耗一览表"判断是否含有聚氯乙烯（PVC）或其他合成树脂原料；
3. 从"三、区域环境质量现状..."→"污染物排放控制标准"→"大气污染物排放标准"提取标准内容（文段+表格）。

### 判定内容

| 序号 | 判定项 | 判定方法 |
|------|--------|----------|
| ① | 污染源覆盖完整性 | 对照产污环节一览表，检查大气标准分析中是否对所有工序、污染物都有对应标准描述 |
| ② | 标准-工序-污染物-排放形式匹配 | 对每个污染源，核对"工序+污染因子+排放形式（有组织/无组织）+执行标准"四要素是否完整且正确 |
| ③ | 特征污染物识别 | 若原料含合成树脂（如PVC、聚酰胺等），根据GB31572-2015表4查找对应树脂类型的特征污染物（如氨、氯乙烯等）及排放限值，判断报告是否遗漏 |
| ④ | 排放限值表格数据 | 根据表头信息识别排放形式和污染因子，逐项核对限值数值 |

### 特征污染物对照

当原辅材料含合成树脂时，从GB31572-2015表4"适用的合成树脂类型"查找：

```text
原料/树脂 → 特征污染物 → 排放限值 → 与报告填报对比
```

例如：聚酰胺树脂→特征污染物"氨"→排放限值30mg/m³→检查报告大气污染物排放标准表格中是否包含氨及限值是否正确。

### 输出结论格式

- **完整/不完整**：污染源覆盖是否完整（不完整时列出缺少的工序/污染物）；
- **相符/不相符**：各污染因子排放执行标准描述是否与知识库/参数知识相符（不相符时列出错误项）；
- **无误/存在错误**：排放限值数据是否正确（存在错误时列出污染物+错误限值+正确限值）。
