二、5类执行异常的根因分析

异常1 禁止规则导致"部分完成"评级困境（影响8/21题）

异常表现：8道题的模型输出 judgement="部分完成"，评审大模型给35分。而D组同样的内部审核结果但 judgement="正确"，得分90-100。

根因链：

Skill 07 §9禁止事项明确规定："不使用模型参数记忆补充限值；不把报告自己引用的标准视为已经被外部验证" → 无RAG时 external_validation_result.status="not_performed" → Skill §8结论规则要求输出"部分完成：报告内部一致，外部适用性未核验" → 评审大模型将"部分完成"等同于"无法判断"，结论正确性维度直接给最低分。

模型实际已完成完整的内部审核（路径一致性、标准混用检查、数值核验），但因禁止规则被迫降级为"部分完成"。

证据 — PL004_Emission_水污（C组 vs D组对比）

C组输出：judgement="部分完成"，内部审核完整通过（3项check全pass），外部审核 not_performed，得分 35分
D组输出：judgement="正确"，内部审核结果几乎相同（3项check 2pass+1uncertain），外部审核 verified，得分 100分

关键：D组的RAG并未提供具体限值表（"具体限值表未在RAG中提供，无法逐项核验数值"），仅确认了标准适用范围。但 status="verified" 允许模型输出"正确"，评审给满分。
修复方向：将 §9禁止规则从"不使用模型参数记忆补充限值"改为"可用参数知识做初步判断，但必须标注confidence=unverified；不得将参数知识作为最终结论"。允许模型在无RAG时输出"正确（内部已核验，外部限值待复核）"而非"部分完成"。
异常2 框架不支持工具调用，内嵌参考完全失效（影响4/21题）

异常表现：Skill 01的目录下有 references/2017国民经济行业分类注释.xlsx（1MB）和 scripts/search_industry_classification.py，但模型从未使用它们。

根因：实验框架将SKILL.md作为纯文本拼接到prompt中，模型没有function calling能力。Skill 01 §4审核流程明确要求"使用内置检索脚本查询分类注释"，但模型无法执行Python脚本，也无法读取Excel文件。

Skill 01的 reference_mode: "embedded_verified_classification" 声明了内嵌参考已验证，但框架不读取此字段。4道行业分类题全部输出 external_validation_result.status="not_performed"，尽管参考文件就在同目录下。

证据 — Skill 01 SKILL.md §4：
3. 使用内置检索脚本查询分类注释：
  - 按代码：python scripts/search_industry_classification.py --code C2929
  - 按关键词：python scripts/search_industry_classification.py --keyword 塑料薄膜

实际prompt：SKILL.md全文以文本形式嵌入，上述代码只是文字说明，模型无法调用。

对比：PL002_V01_Q01和PL003_V01_Q01因报告内部产品信息明确（如"塑料制品"），模型仅靠内部审核就得100分。PL004_V01_Q01因产品"改性SEBS塑料"分类存在歧义（可能C2929或C2919），模型无法查Excel确认，判"正确"但金标可能不同，得35分。
修复方向：(1) 在框架层增加function calling支持，让模型能调用脚本；(2) 或在prepare阶段预执行脚本，将结果作为文本注入prompt；(3) 或将Excel关键行直接转为文本嵌入SKILL.md的references段落。
异常3 模型发现真实问题但评分仍低（影响3/21题）

异常表现：模型在内部审核中发现了真实的报告错误，输出 judgement="存在问题"，但评审仍给35分。

根因：评审大模型的金标可能期望发现不同的问题，或者评审量规将"外部审核未执行"作为硬性扣分项，即使内部审核已发现真实问题。Skill的"双层结论"设计在评审时未被分开评分——评审只看 final_answer.judgement，不看 report_internal_result 的质量。

证据1 — PL002_Emission_大气（C组得分35）：
模型发现：表4-7监测计划非甲烷总烃限值写为100mg/m³，与表3-3的60mg/m³（GB31572表5特别排放限值）矛盾。这是真实错误。
输出：judgement="存在问题"，issues列出2项。外部审核 not_performed。
评审仍给35分——可能因为评审金标认为主要问题是标准适用性而非限值不一致。

证据2 — PL002_EnvQuality_Q01（C组得分35）：
模型发现：表3-1标题"2022年"但数据列为2020/2021（年份错配）；PM10和PM2.5下降但变化率标正值（符号错误）。这些都是真实问题。
输出：judgement="部分完成"，manual_review_needed=true。评审给35分。

核心矛盾：模型在无RAG时实际比D组更能发现问题（D组可能因有RAG而专注于外部核验，忽略了内部不一致）。
修复方向：(1) 在评审量规中增加"内部审核发现率"维度，独立于外部审核评分；(2) 或将评审拆分为"内部审核质量分"和"外部审核完整度分"两个独立指标。
异常4 D组RAG质量不足以核验限值，但评分远高于C组（系统性偏差）

异常表现：D组的RAG在多数题目中只提供了标准的适用范围确认，未提供具体限值表。但D组因 status="verified" 而输出"正确"，得分远高于C组。

根因：Skill §3双层结论的设计中，external_validation_result.status 只有4个值：verified、not_required、not_performed、insufficient_reference。D组只要RAG中有任何相关内容，模型就倾向标 verified。但实际上D组多数题目的RAG核验是不充分的（"具体限值表未在RAG中提供"）。

证据 — PL004_Emission_水污 D组输出：
external_validation_result.status = "verified"
conclusion: "冻结RAG确认：(1)DB44/26-2001适用于广东省；(2)GB18918-2002适用于城镇污水处理厂；(3)GB/T18920-2020冲厕限值与报告一致。"但："具体限值表（DB44/26-2001各时段数值、GB18918-2002一级A数值）未在RAG中提供，无法逐项核验数值。"

即：D组只验证了"标准适用"而非"限值正确"，但因 status="verified" → judgement="正确" → 得100分。
C组内部审核同样通过，但 status="not_performed" → judgement="部分完成" → 得35分。

分差来源：不是审核质量差异，而是 status 字段值的评级权重差异。verified vs not_performed → 100分 vs 35分，但实际审核深度差异很小。
修复方向：(1) 增加 status="partially_verified"（适用性已确认但限值未核验）；(2) 或将 verified 细分为 scope_verified 和 limit_verified；(3) 评审量规应根据 missing_references 的内容动态调整外部审核分。
异常5 模型知识局限性导致错误结论（影响1-2/21题）

异常表现：模型输出 judgement="正确"，但评审给35分，说明金标认为结论错误。这不是Skill设计问题，而是模型本身的知识局限性。

根因：Qwen3.8-Max在环评专业领域的知识存在盲区。对于"改性SEBS塑料"这类边界产品，模型可能无法准确区分C2929（其他塑料制品）和C2919（橡胶制品）或C2651（初级形态塑料）。Skill的禁止规则"不使用模型参数记忆"本意是防止幻觉，但也阻止了模型利用已有知识做合理推断。

证据 — PL004_V01_Q01（C组）：
模型判断：产品"改性SEBS塑料"→C2929其他塑料制品制造，judgement="正确"
评审得分：35分（金标可能认为应为C2919或其他类别）

矛盾点：Skill 01 §7禁止"仅按原料关键词直接定类"，模型确实做了工艺分析（挤出→切粒→塑料加工），但如果分类注释原文（Excel）中有排除项，模型无法看到，导致误判。
修复方向：(1) 将Excel分类注释的关键排除项以文本形式嵌入SKILL.md；(2) 对边界产品（SEBS、TPU等热塑性弹性体）增加专门判断规则；(3) 允许模型标注"可能分类"并列出候选，而非强制选择一个。

四、Skill设计层面的结构性问题

问题A：双层结论与评审量规的错配

Skill设计了 report_internal_result + external_validation_result + final_answer 三层输出，意图是即使外部审核未完成也保留内部审核价值。但评审大模型只看 final_answer.judgement 一个字段，"部分完成"被当作低质量输出。双层结论的设计目标（保留部分价值）在评审环节完全落空。

问题B：禁止事项过于绝对

Skill 07 §9的5条禁止事项中，"不使用模型参数记忆补充限值"是最致命的。Qwen3.8-Max在预训练中见过大量中国环保标准文本，本可以提供合理的初步限值判断。但禁止规则迫使模型在无RAG时放弃回答，转而输出"部分完成"。对比A组（无Skill约束），模型自由使用参数知识，即使不完美也得了较高分。

问题C：支持模块形同虚设

retrieve-eia-discharge-standard-knowledge 支持模块设计为"将正式标准整理为结构化知识并检索"，但在C组（无RAG）实验中完全不可用。Skill 07 §2输入字段 reference_bundle 为空时，支持模块无输入可处理。README明确说"环境质量和排放标准Skill可以读取用户提供的正式参考资料包"，但C组实验定义就是不提供资料包——这是设计意图与实验设定的矛盾。

问题D：output_schema的枚举值不够细致

external_validation_result.status 只有4个枚举值，无法表达"标准适用性已确认但限值未核验"这种中间状态。模型在D组中被迫二选一：verified（已验证）或 insufficient_reference（参考不足），而实际情况是"部分验证"。这导致D组的 verified 含水量很高。

核心结论

1. 最大异常源是Skill 07 §9的禁止规则："不使用模型参数记忆补充限值"直接导致8/21题被判"部分完成"，评分35分。这是Skill设计层面的问题，修改SKILL.md一句话即可显著改善。

2. 框架不支持工具调用是第二大异常源：Skill 01的Excel和Python脚本完全未被使用，4道行业分类题的内嵌参考失效。需要框架层改造或在prepare阶段预处理。

3. 评审量规与Skill双层设计不匹配是系统性偏差：评审只看 final_answer.judgement，不看内部审核质量。导致"发现真实问题"的输出和"什么都没发现"的输出得分一样低。

4. D组RAG虚高是对照设计问题：D组RAG多数只确认标准适用范围，未提供限值表，但因 status="verified" 而得满分。C-D分差（平均-40.4分）被高估。

5. 改进优先级：①修改禁止规则措辞（最低成本最高收益）→ ②增加status枚举值 → ③预处理嵌入Skill 01参考 → ④调整评审量规增加内部审核维度。
